## 2주차 질문
> 처음 설계한 API 명세서에 변경사항이 있었나요? 변경 되었다면 어떤 점 때문 일까요?
>첫 설계의 중요성에 대해 작성해 주세요!

크게 변경사항은 없었습니다. 초기 설계 단계에서 요구사항을 명확히 파악하고 전체 시스템의 구조와 흐름을 정리해둔다면 개발 전반에 걸쳐 기준이 되어 혼란을 줄이고, 팀원 간 원활한 소통과 협업을 가능하게 합니다

> ERD를 먼저 설계한 후 Entity를 개발했을 때 어떤 점이 도움이 되셨나요?

ERD 설계대로 Entity를 개발하면되서 편하고 데이터 무결성을 보장하는데 도움을 줍니다.
 
> JWT를 사용하여 인증/인가를 구현 했을 때의 장점은 무엇일까요?

클라이언트측에서 인증 정보를 가지고 있기때문에 서버에서 따로 인증 정보를 저장안해도 되며 그로인해 확장성면에서 이점이 있습니다.

> 반대로 JWT를 사용한 인증/인가의 한계점은 무엇일까요?

한번 발급된 토큰은 무효화하기가 어렵기때문에 토큰 탈취시 보안에 취약합니다.
그렇기 때문에 토큰의 유효시간은 짧게 잡는게 좋습니다.

> 만약 댓글 기능이 있는 블로그에서 댓글이 달려있는 게시글을 삭제하려고 한다면 무슨 문제가 발생할까요? Database 테이블 관점에서 해결방법이 무엇일까요?

게시글 삭제시 연관관계로 이어진 댓글은 고아 상태가 되어 테이블 정합성에 문제가 생깁니다.
정합성을 보장하기 위해 게시글 삭제시 댓글도 삭제되도록 구현하여야합니다.

> IoC / DI 에 대해 간략하게 설명해 주세요!

IoC (제어의 역전): 객체의 생성과 관리 책임을 애플리케이션이 아닌 외부 컨테이너나 프레임워크에 위임하여, 모듈 간의 결합도를 낮추고 시스템의 확장성을 높이는 설계 원칙입니다.

DI (의존성 주입): IoC를 구현하는 한 가지 방법으로, 필요한 의존 객체를 외부에서 주입받음으로써 클래스 간의 강한 결합을 피하고, 테스트와 유지보수를 용이하게 만드는 기법입니다.
